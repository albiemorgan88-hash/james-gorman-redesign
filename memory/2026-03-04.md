### End-to-End Draw Flow (Full Methodology)

**User Journey:**
1. **Sign Up** → `ardmorecricket.com/signup` → email + password → Supabase Auth creates user → `profiles` table populated → welcome email sent from `draws@ardmorecricket.com` via Resend
2. **Pick Numbers** → `ardmorecricket.com/draw` → grid shows 500 numbers (5 pages of 100) → blue = available, grey = taken, purple = subscribed, gold = selected → client fetches taken numbers from both `number_selections` AND `draw_subscriptions` tables
3. **Assign Names** → optional text field per number (e.g. "Stacey", "Da") → stored as JSON `assigned_names` in DB
4. **Choose Payment Mode** → subscription (auto-renew weekly) or one-off (this week only)
5. **Checkout** → POST to `/api/checkout` → creates Stripe Checkout Session with metadata (user_id, club_id, numbers, names, payment mode) → redirects to Stripe
6. **Stripe Payment** → user pays → Stripe fires `checkout.session.completed` webhook to `/api/webhooks/stripe`
7. **Webhook Processing:**
   - **Subscription path:** creates `draw_subscriptions` record + `number_selections` record + `payments` record
   - **One-off path:** creates/merges `number_selections` record + `payments` record
   - Both paths: send purchase confirmation email to user + admin notification to contact@bluecanvas.ai & Ardmorecc1879@hotmail.com
8. **Success Page** → `ardmorecricket.com/draw/success` → confetti, gold number circles, "what happens next" section
9. **Optimistic Cache** → client stores `optimistic_purchased` in localStorage so numbers show immediately as taken without waiting for page reload

**Weekly Draw Execution (Friday 7PM):**
- Cron triggers draw engine (`run-draw.js` in ardmore-draw-live repo)
- Provably fair: SHA-256 hash of seed published before, seed published after
- 3 winning numbers drawn from 500
- Prizes: 25% (1st), 15% (2nd), 10% (3rd) of pot → 50% total to winners, 50% to club
- Draw results emailed to all participants via `sendDrawResults()` — winners get celebration email, non-winners get results + "better luck next week"
- Live draw animation at `/draw/live` or GitHub Pages demo link

**Subscription Renewals:**
- Stripe fires `invoice.paid` with `billing_reason: subscription_cycle`
- Webhook creates new `number_selections` entry for the new week
- Updates `draw_subscriptions` period dates
- Records renewal payment

**Failed Payments:**
- `invoice.payment_failed` → subscription marked `past_due` in DB
- Numbers still show as taken (purple) but flagged

**Cancellations:**
- `customer.subscription.deleted` → subscription marked `cancelled`
- Numbers released (no longer show as taken)

**Data Tables:**
- `clubs` — club config, Stripe Connect account, draw settings
- `profiles` — extends Supabase auth.users, Stripe customer ID
- `number_selections` — per-week number picks (active/paused/cancelled)
- `draw_subscriptions` — recurring subscriptions with numbers + assigned names
- `payments` — all payment records with metadata
- `draws` — draw results with winning numbers, seed, pot amount
- `draw_entries` — individual entries per draw
